# Story: Add Merge to data pipeline

## Summary

As a platform engineer,  
I want to add Merge to the datapipeline so that the many CSVs (purchase data uploaded by the user) are consolidated into 
one CSV (`purchase_data.csv`) for later steps of the datapipeline.

## Background

The data pipeline is orchestrated by AWS Step Functions. S3 buckets hold the artifacts between stages. Users 
upload their purchase data to the input bucket.

The current pipeline elements are:
```text
Normalizer Classifier PIICalculation
```
Let's add Merge after Normalizer:
```text
Normalizer Merge Classifier PIICalculation
```

The intended execution flow is:
```text
Normalizer -> Merge -> Classifier -> PIICalculation
```

Pipeline data should be passed between stages using S3 object URIs. PDF, CSV, and JSON file contents should not be 
passed inline through Step Functions state.

## Existing Architecture
There are two S3 buckets:
- `input-bucket`: Holds initial user uploads and intermediate artifacts used and produced across pipeline stages. 
  Normalizer creates multiple CSV files in `<ticket>/uploads/` that Merge consolidates into a single CSV called `purchase_data.csv` at `<ticket>/purchase_data.csv`. `purchase_data.csv` is subsequently consumed by Classifier (Batch).
- `output-bucket`: Holds final pipeline outputs (e.g., `pii-report.json`). It is not used by Merge.

`s3.tf` refers to these buckets as:
- `<input-bucket>` = `"${var.app_name}-data-pipeline-input-${var.environment}"`
- `<output-bucket>` = `"${var.app_name}-data-pipeline-output-${var.environment}"`
This is the standard for input and output file creation for all Step Functions stages.

## Target Architecture

```text 
Step Functions State Machine | 
v s3://<input-bucket>/<ticket number>/uploads/*.pdf |
v Task 1: run Normalizer -> *.csv |
v s3://<input-bucket>/<ticket number>/uploads/*.csv |
v Task 2: merge -> purchase_data.csv |
v s3://<input-bucket>/<ticket number>/purchase_data.csv |
v Task 3: Submit Classifier AWS Batch Job | 
v s3://<input-bucket>/<ticket-number>/classified.csv | 
v Task 4: Invoke PIICalculation Lambda | 
v s3://<output-bucket>/<ticket-number>/pii-report.json
```

## Proposed Workflow Input

The Step Functions execution accepts an input payload structured as:
```json
{
  "ticket": "123456789",
  "uploads": "s3://pii-data-pipeline-input-dev/123456789/uploads/",
  "inputCsv": "s3://pii-data-pipeline-input-dev/123456789/purchase_data.csv",
  "classifiedCsv": "s3://pii-data-pipeline-input-dev/123456789/classified.csv",
  "piiReportJson": "s3://pii-data-pipeline-output-dev/123456789/pii-report.json"
}
```

## Step Functions State Machine Behavior

The state machine will have four primary task states:
```text
Normalize -> Merge -> Classify -> CalculatePII -> Success
```

### State 1: `Normalize`
`Normalize` invokes the Normalizer Lambda with the uploads S3 URI to convert uploaded PDF files into CSV files.
#### Inputs:
- `ticket`
- `uploads`
#### Expected Behavior:
1. Read uploads from S3.
2. Submit uploads to Normalizer Lambda (`pdf2csv`).
3. Normalizer creates CSV files for each PDF file in uploads.
4. Complete successfully and transition to `Merge`.

### State 2: `Merge`
`Merge` consolidates the individual CSVs generated by `Normalize` into a single `purchase_data.csv`.
#### Inputs:
- `ticket` (mapped from `$.ticket`)
- `input-s3-uri` (mapped from `$.uploads`)
- `output-s3-uri` (mapped from `$.inputCsv`)
#### Step Functions Task Configuration:
- **Resource:** `arn:aws:states:::lambda:invoke`
- **FunctionName:** `aws_lambda_function.merge.arn`
- **Parameters:**
  ```json
  {
    "ticket.$": "$.ticket",
    "input-s3-uri.$": "$.uploads",
    "output-s3-uri.$": "$.inputCsv"
  }
  ```
- **ResultPath:** `$.mergeResult`
- **Next:** `Classify`
#### Expected Behavior:
1. Read CSVs from the S3 path (directory) designated by `input-s3-uri`.
2. Consolidate records across CSV files into a unified dataset.
3. Write merged CSV to S3 path designated by `output-s3-uri` (`purchase_data.csv`).
4. Complete successfully and transition to `Classify`.

### State 3: `Classify`
`Classify` submits the existing Classifier AWS Batch job (`$.inputCsv` -> `$.classifiedCsv`), then transitions to `CalculatePII`.

### State 4: `CalculatePII`
`CalculatePII` invokes the PIICalculator Lambda (`$.classifiedCsv` -> `$.piiReportJson`), then marks execution as complete.

## Lambda Event Contract

The Merge Lambda receives an event matching the kebab-case key format used by the pipeline:
```json 
{ 
  "ticket": "123456789", 
  "input-s3-uri": "s3://pii-data-pipeline-input-dev/123456789/uploads",
  "output-s3-uri": "s3://pii-data-pipeline-input-dev/123456789/purchase_data.csv"
}
```

The Lambda response includes execution information for Step Functions observability:
```json 
{ 
  "ticket": "123456789", 
  "status": "SUCCEEDED", 
  "output-s3-uri": "s3://pii-data-pipeline-input-dev/123456789/purchase_data.csv"
}
```

## Infrastructure Scope

Update the Terraform module `datapipeline` to include:

- AWS Step Functions state machine updated to place Merge between Normalize and Classify (`Normalize -> Merge -> Classify -> CalculatePII`).
- Task state to invoke the Merge Lambda function with `ResultPath = "$.mergeResult"`.
- IAM role for Step Functions execution updated with permissions to invoke Merge Lambda (`aws_lambda_function.merge.arn` and `${aws_lambda_function.merge.arn}:*`).
- AWS Lambda function definition for Merge:
  - Architecture: `arm64`
  - Runtime: `python3.12`
  - Handler: `merge.lambda_handler.handler`
  - S3 bucket: `aws_s3_bucket.input.id`
  - S3 key: `var.merge_lambda_s3_key`
- Lambda execution role for Merge with `s3:GetObject`, `s3:PutObject`, and `s3:ListBucket` permissions on the input bucket.
- CloudWatch log group for the Merge Lambda (`/aws/lambda/${var.app_name}-merge-${var.environment}`) with retention configured via `var.lambda_log_retention_days`.
- Environment-specific variables:
  - `merge_lambda_s3_key` (default `"lambdas/merge.zip"`)
  - `merge_lambda_handler` (default `"merge.lambda_handler.handler"`)
  - `merge_lambda_runtime` (default `"python3.12"`)
  - `merge_lambda_timeout_seconds` (default `60`)
  - `merge_lambda_memory_size` (default `512`)
- Module outputs:
  - `merge_lambda_arn`
  - `merge_lambda_name`
  - `merge_lambda_role_arn`
  - `merge_log_group_name`

## Merge Lambda Execution Role

The Merge Lambda execution role provides:

- Read `*.csv` files from the input bucket's `<ticket>/uploads/` path (`s3:GetObject`).
- List objects in the input bucket (`s3:ListBucket`) to discover CSVs in the uploads directory.
- Write merged `purchase_data.csv` to the input bucket's `<ticket>/` path (`s3:PutObject`).
- Write logs to CloudWatch (`logs:CreateLogStream`, `logs:PutLogEvents`).

## Retry and Error Handling

The state machine includes retry behavior for transient infrastructure failures.

### Merge Lambda Retry Policy

Because Merge is fast and cheap:
- Retry transient Lambda service and throttling errors with exponential backoff.
- Use a 60-second default Lambda timeout.
- Fail clearly on unhandled validation errors.

Step Functions task retry configuration:
```json
{
  "ErrorEquals": [
    "Lambda.ServiceException",
    "Lambda.AWSLambdaException",
    "Lambda.SdkClientException",
    "Lambda.TooManyRequestsException"
  ],
  "IntervalSeconds": 2,
  "MaxAttempts": 3,
  "BackoffRate": 2.0
}
```

## Failure Behavior

- If `Merge` fails, `Classify` must not run.
- Uploaded CSVs in the input S3 bucket remain available after Merge execution.
- Failed executions preserve S3 artifact URIs in the execution history for inspection and retry.

## Observability Requirements

The infrastructure provides:

- CloudWatch logs for Step Functions executions.
- CloudWatch log group for the Merge Lambda (`/aws/lambda/${var.app_name}-merge-${var.environment}`).
- Step Functions task state clearly named `Merge`.
- Execution input and output payloads capturing S3 artifact URIs.
- Errors visible at the failed state level in Step Functions console and logs.
- Lambda response containing `ticket`, `status`, and `output-s3-uri`.

## Acceptance Criteria

- The state machine contains a `Merge` Lambda task state positioned between `Normalize` and `Classify`.
- The Merge workload runs as an AWS Lambda function on `arm64` architecture.
- CSV file contents are not passed inline through Step Functions state; S3 object URIs are used.
- The Merge Lambda invocation payload passes:
  - `ticket`
  - `input-s3-uri`
  - `output-s3-uri`
- The Merge Lambda execution role has read, write, and list permissions scoped strictly to the input bucket (`s3:GetObject`, `s3:PutObject`, `s3:ListBucket`).
- Step Functions execution role has `lambda:InvokeFunction` permissions for the Merge Lambda.
- CloudWatch log group for Merge Lambda is provisioned with configurable retention.
- Terraform module outputs for Merge (`merge_lambda_arn`, `merge_lambda_name`, `merge_lambda_role_arn`, `merge_log_group_name`) are exported.
- `terraform plan` succeeds without errors.
- `terraform apply` succeeds in the target environment.
- A test execution of the state machine runs through `Normalize -> Merge -> Classify -> CalculatePII` and produces `purchase_data.csv` at the expected S3 path.

## Out of Scope
- Frontend integration.
- API changes for starting pipeline executions.
- EventBridge or S3-triggered automatic execution.
- Implementation of the Merge Python application code (provided at `lambdas/merge.zip`).

## Clarifications and Decisions

- **Lambda Package & S3 Key:** The deployment package artifact is located in the input S3 bucket at `lambdas/merge.zip`.
- **Lambda Runtime and Handler:** `python3.12` runtime with three-part handler `merge.lambda_handler.handler` (configurable via `var.merge_lambda_handler`).
- **Lambda Event Contract:** Uses kebab-case keys (`ticket`, `input-s3-uri`, `output-s3-uri`) matching Normalizer and PIICalculator Lambda conventions.
- **Input Path:** `s3://<input-bucket>/<ticket-number>/uploads/` (mapped from workflow `$.uploads`).
- **Output Path:** `s3://<input-bucket>/<ticket-number>/purchase_data.csv` (mapped from workflow `$.inputCsv`).
- **S3 Bucket Permissions:** Merge Lambda execution role is strictly scoped to the input bucket; the output bucket is not used by Merge.
- **Step Functions ResultPath:** `$.mergeResult`.
- **Lambda Networking:** The Merge Lambda runs in the default Lambda service network (not VPC-attached).
- **Logging:** Step Functions uses standard CloudWatch logging (`/aws/vendedlogs/states/...`) with logging level `ALL` and execution data included.
- **Module Outputs:** Standard full outputs exported (`merge_lambda_arn`, `merge_lambda_name`, `merge_lambda_role_arn`, `merge_log_group_name`).
